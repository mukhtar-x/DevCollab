Dual-Workspace Routing ArchitecturePersonal Workspaces: Endpoints operating under implicit owner privileges. Bypasses collaborative RBAC checks to provide an isolated developer playground.Collaborative Workspaces: Strict RBAC-enforced environments where every API endpoint requires active membership validation and action-string capabilities.2. Backend-as-Source-of-Truth RBACPermissions are defined as granular action strings (edit_task, delete_task, add_comment, manage_members, etc.) rather than hardcoded role checks.  Backend services calculate and attach active user permissions (userPermissions) and role name (currentUserRole) directly into API payloads returned to the client.Authorization middleware validates request tokens and project permissions at the Express controller layer before any database operation executes.3. $O(1)$ Frontend UI GuardingA custom usePermissions React hook extracts active capability arrays from Redux state and exposes a hasPermit(permission) lookup function.Internal lookups leverage a JavaScript Set data structure for $O(1)$ time complexity on conditional UI rendering, hiding or disabling UI triggers (buttons, inputs, modals) based on server-provided capabilities.  📅 Day-by-Day Implementation SummaryWeek 1: Foundation (Jul 03 – Jul 09)Day 01: Auth Hardening & Profile SchemaBackend: Refactored JWT authentication pipeline, implemented refresh token rotation, configured express-rate-limit for security, and expanded the extended User model (bio, avatar, socialLinks, skills).Endpoints: Built GET /api/v1/users/me and PATCH /api/v1/users/me following the strict Route $\rightarrow$ Controller $\rightarrow$ Service $\rightarrow$ Repository architecture.
